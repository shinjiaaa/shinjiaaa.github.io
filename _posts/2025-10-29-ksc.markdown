배경 지식

YOLO: 객체 탐지 알고리즘 중 하나 - 이미지를 보고 객체의 위치와 클래스를 예측

LIME: 모델이 어떤 feature에 영향을 받아 특정 예측 결과를 냈는지를 설명하는 기법
이미지의 경우 Super Pixel 단위로 구역을 나눈 뒤, 각 영역을 부분적으로 제거하거나 변화시켜(해당 과정을 마스킹이라고 한다) 모델에 적용하여 반응(예측률)을 확인함 -> 해당 과정을 통해 전체 이미지 중 어떤 부분이 예측에 중요한 역할을 했는지 시각적으로 제공함

Super Pixel: 이미지의 인접한 픽셀들 중 비슷한 특징을 가진 픽셀들을 하나의 덩어리로 묶은 단위 - 예측에 영향을 준 부분의 정확도를 분석한 결과 \*슈퍼 픽셀 산출 원리: 최종 클래스 예측에 얼마나 기여하는지 weight를 반환함

이전 실패 요인

이전에 사용하던 데이터셋은 디렉토리 구조가 다르고(Segment, Depth), 라벨링이 되어 있지 않은 드론 충돌 영상 데이터셋이었음 -> 이 데이터셋을 기존에 사용하던 데이터셋(images, labels)과 통합하는 과정에서 잘못돼 모델 성능이 낮게 평가됨

문제 해결 시도

1. 자동 라벨링 -> 객체를 정확히 잡지 못해 no detection -> class 정의 및 라벨링 실패
2. 수동 라벨링 (labelimg) -> train 폴더에만 300장 가량 시도 후 진행 -> no detection 문제 발생
3. 라벨링 되어 있는 다른 데이터셋 찾아서 새로 학습....... ㅜㅜ 성공

진행 상황

1. 드론 충돌 이미지 데이터셋 & 드론 시점의 비디오 데이터셋 학습 - 객체 탐지 모델 개발 (목표: mAP@0.5 0.6)

2. 객체 탐지 모델을 기반으로 충돌 분류 모델 개발

3. LIME 기법을 충돌 분류 모델에 적용
   3-1. 탐지된 객체에 대해 충돌 위험이 큰 영역을 슈퍼 픽셀(mask)로 시각화
   3-2. 슈퍼 픽셀 기반 충돌 위험률 산출
   3-3. LIME의 판단 근거를 Ai를 통해 UI 또는 터미널에 자연어로 제공

성공 조건

1. 감지한 객체에 대하여 클래스를 정확히 산출할 것
2. 슈퍼 픽셀은 감지 객체 외의 영역에 나타나지 않도록 할 것
3. 사용자가 납득할 수 있는 판단 근거를 제시할 것

디벨롭 사항

1. 정확히 하나의 객체만을 탐지하여 bbox(bounding-box) 산출 ✅
   1-1. 카메라 캘리브레이션 적용(감지 성능 높이기 위함)하여 객체의 실제 거리(D) 산출 -> 거리가 가장 가까운 객체 1개에 한하여 bbox 씌우기
   => 즉, D가 작다 = 객체가 가까이 있다 = 충돌 가능성이 높은 객체

2. mAP@0.5 기준 전체 클래스에 대하여 0.6 이상의 성능을 보이도록 추가 학습 진행
   2-1. building class의 image 수가 상대적으로 적음 -> other에 합치기 ✅
   3-2. car class에 대한 데이터셋이 가장 많으므로 파인 튜닝 시 클래스마다 가중치를 다르게 두어 train 진행 (클래스 불균형 완화를 위함) - 계속하여 진행 중

3. Ai 기반 판단 근거 송출 시 납득 가능한 근거 산출
   3-1. 프롬프트 요구사항 정확히 기술
   3-1-1. class에 대하여 슈퍼 픽셀이 왜 해당 영역에 표시되었는지 근거 설명 - 카메라 화면 기반으로 산출하지 못하고 있기에 해결 방안 모색 필요
   3-1-2. JSON 형태로 전달 ✅
   3-2. UI에 반환

디벨롭 후 구동 방식

1. 객체 탐지 모델(YOLO)을 통해 객체(장애물)을 탐지한다. 이때 객체와 단안 카메라의 거리(Depth)를 산출한 후, 가장 신뢰도가 높게 감지된 객체에 대하여 bbox를 씌운다.
2. 감지된 객체를 충돌 분류 모델에 전달하여 충돌을 판단(이진 분류)한다.
3. 충돌 판단 시, LIME을 적용하여 판단에 기여한 영역(슈퍼 픽셀)을 산출한다.
4. 충돌이라 판단된 객체에 대하여 깊이 정보(Depth)를 결합해 실제로 장애물과 드론이 충돌할 확률을 수치화한다.
5. 실시간 카메라 화면(bbox, super pixel), 충돌 확률, 판단 근거를 자연어로 UI에 제공한다.
